# CORS and GitHub Codespaces

## `pf-signin` and the web app manifest

A private GitHub Codespaces forwarded port may redirect an asset request to
GitHub's `pf-signin` endpoint. That response is generated by GitHub rather
than the Vite application, so PowerPay cannot add an
`Access-Control-Allow-Origin` header to it.

Browsers fetch web app manifests under CORS rules. PowerPay therefore removes
the manifest link from Vite HTML during development. Production builds keep
the normal manifest link.

To test the manifest from Codespaces, make port 5173 public or deploy the
production build behind a same-origin host.

## API configuration

Configure exact production origins:

```env
POWERPAY_CORS_ORIGINS=https://merchant.example,https://admin.example
```

The API now:

- emits `Access-Control-Allow-Origin` only for a valid, permitted origin;
- does not substitute an unrelated configured origin;
- does not use the literal `null` value as a denial fallback;
- validates preflight methods and requested headers;
- returns `204` only for valid preflight requests;
- emits `Vary` when an explicit origin allowlist is active.

The development default is `*` without credentialed CORS.
